# Crew ビュー 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** orb のウィンドウ上部 1/4 に、アクティブタブのペインを 1 体ずつのアイソメトリックなキャラとして描く帯を追加し、既存の `PaneStatus` に連動して働かせる。

**Architecture:** 状態判定は一切新設しない。既存の `agent-status.ts` → `paneStatus` ストアに乗るだけ。純ロジック（席割り・状態→見た目の写像・アイソメ座標）を `src/crew/model.ts` に隔離して vitest で固め、`src/crew/Crew.svelte` は受け取った配列を描くだけにする。Rust 側は一切変更しない。

**Tech Stack:** Svelte 5（runes）/ TypeScript / vitest / 素の CSS（`transform` と `@keyframes` のみ）

## Global Constraints

- **Rust（`src-tauri/`）は一切変更しない。** 新規 IPC コマンド・Tauri イベント・`config.toml` フィールドを追加しない。
- **状態判定を新設しない。** 見た目は `src/core/agent-status.ts` の `PaneStatus` から写すだけ。判定ロジックを Crew 側に複製しない。
- **アニメーションは compositor-only。** `transform` と `opacity` のみを動かす。`top`/`left`/`width`/`height`/`margin` はアニメーションさせない（`PERFORMANCE.md`）。
- **JS の毎フレームループを持たない。** アニメーションはすべて CSS `@keyframes`。`requestAnimationFrame` の使用は「入場時に 1 回だけ位置をフリップする」用途に限る。
- **既存のヘルパを再利用する。** `leafIds()`（`src/layout/tree.ts:80`）、`leafInfoMap()`（`src/layout/tree.ts:132`）、`STATUS_LABEL`（`src/core/agent-status.ts:48`）、`persistedBool`（`src/store/appStore.ts:151`、同ファイル内の非 export 関数）。
- **コメントは日本語**、既存ファイルと同じ密度・語調に合わせる。コミットメッセージは英語。
- **色は `src/styles/app.css` の CSS 変数のみ使う**: `--teal #2dd4bf` / `--mint #6ee7b7` / `--violet #a78bfa` / `--red #ff5c8a` / `--grey #8ba8a3` / `--surface #173832` / `--dark #0a1a17` / `--fg #e6fffa`。生の hex 値をコンポーネントに直書きしない（例外: 仕様に無い黄色は `#fbbf24` を `--crew-amber` としてコンポーネント内に定義する）。
- **アイソメ格子は 4 列 × 2 行 = 8 席固定**。タイルは幅 96px・高さ 48px（2:1）。
- 検証コマンド: `pnpm test`（vitest）/ `pnpm check`（svelte-check）/ `pnpm tauri dev`（実機）。

## 仕様からの意図的な逸脱（2 点）

**1. アセットを最後に回す。** 仕様（`docs/superpowers/specs/2026-08-06-crew-view-design.md`）はキャラの絵に Kenney の CC0 スプライトを使うと書いているが、本計画では **Task 1〜4 を CSS 図形だけで完成させ、スプライト差し替えを最後の任意タスク（Task 5）に回す**。

理由: ユーザーの明示的な要望が「見た目はいったん動作から見たい」であること、および外部アセットの中身（実ファイル名）が未確認で、そこに前段のタスクを依存させると全体が止まるため。Task 4 まで完了した時点で実物を見て、Task 5 を実施するか CSS 図形のまま確定するかを判断する。

**2. 向きを 4 方向から 2 方向に減らす。** 仕様は back / front / left / right の 4 方向を使うと書いているが、本計画の `CrewFacing` は `back | front` の 2 種だけにする。

理由: 向きの唯一の意味は「手が要るか否か」（＝こちらを向いているか）であり、席は格子に固定されていて左右方向を向く必然が無い。歩行中の向きも、移動が水平方向のみ（席詰め・左からの入場）なので左右の区別が要らない。使わない状態を型に持たせない。

```ts
/**
 * Crew ビュー（ペイン＝キャラ）の純ロジック。DOM/Svelte/Tauri 非依存＝vitest 対象。
 *
 * 状態判定そのものは一切持たない。agent-status.ts が PTY 出力から決めた PaneStatus を
 * 「見た目」へ写すだけ（判定を二重実装するとバッジ・通知・キャラの表示がズレるため、
 * agent-status.ts 冒頭のコメントと同じ方針で単一の真実に乗る）。
 */
import type { PaneStatus } from "../core/agent-status";
import type { PaneRole } from "../layout/tree";

/** キャラの動作。PaneStatus と 1:1 で対応する（+ バッジ無しの idle）。 */
export type CrewAction = "typing" | "calling" | "urgent" | "resting" | "down" | "idle";

/** キャラの向き。奥(デスク側)を向いていれば作業中、こちらを向いていれば人間の手が要る。 */
export type CrewFacing = "back" | "front";

export const SEAT_COLS = 4;
export const SEAT_ROWS = 2;
export const MAX_SEATS = SEAT_COLS * SEAT_ROWS;

/** アイソメ 1 タイルの見かけの大きさ(px)。菱形なので 幅:高さ = 2:1。 */
export const TILE_W = 96;
export const TILE_H = 48;

export interface CrewMember {
  paneId: number;
  /** 0..MAX_SEATS-1。席番号がそのままアイソメ座標に写る。 */
  seat: number;
  /** ホバー時に出す名前。案件ランチャー由来の label、無ければ "pane N"。 */
  label: string;
  role: PaneRole;
  status: PaneStatus | null;
  action: CrewAction;
  facing: CrewFacing;
}

export function actionForStatus(s: PaneStatus | null | undefined): CrewAction {
  switch (s) {
    case "running":
      return "typing";
    case "waiting":
      return "calling";
    case "attention":
      return "urgent";
    case "done":
      return "resting";
    case "failed":
      return "down";
    default:
      return "idle";
  }
}

/**
 * 「人間の手が要る状態だけこちらを向く」という一本のルールで向きを決める。
 * 作業中(typing)・完了直後(resting)・待機(idle) はデスク側を向いたまま＝放っておいてよい。
 */
export function facingForAction(a: CrewAction): CrewFacing {
  return a === "calling" || a === "urgent" || a === "down" ? "front" : "back";
}

/** 席番号 → 格子座標。左上から横に詰める（4 列で折り返す）。 */
export function seatToCell(seat: number): { col: number; row: number } {
  return { col: seat % SEAT_COLS, row: Math.floor(seat / SEAT_COLS) };
}

/**
 * 格子座標 → アイソメの画面オフセット(px)。2D アイソメの標準変換。
 * 原点(0,0)は格子の (0,0) タイル中心で、実際の中央寄せは描画側が行う。
 */
export function cellToIso(cell: { col: number; row: number }): { x: number; y: number } {
  return {
    x: (cell.col - cell.row) * (TILE_W / 2),
    y: (cell.col + cell.row) * (TILE_H / 2),
  };
}

export function seatToIso(seat: number): { x: number; y: number } {
  return cellToIso(seatToCell(seat));
}

/**
 * ペイン一覧（leafIds の順）＋付帯情報＋状態から、描画すべきキャラ配列を作る。
 * paneIds の順序はペイン木の左→右/上→下で安定しているので、そのまま席順にできる。
 */
export function buildCrew(
  paneIds: number[],
  info: Map<number, { role?: PaneRole; label?: string }>,
  status: ReadonlyMap<number, PaneStatus>,
): CrewMember[] {
  return paneIds.slice(0, MAX_SEATS).map((paneId, seat) => {
    const i = info.get(paneId);
    const s = status.get(paneId) ?? null;
    const action = actionForStatus(s);
    return {
      paneId,
      seat,
      label: i?.label || `pane ${paneId}`,
      role: i?.role ?? "shell",
      status: s,
      action,
      facing: facingForAction(action),
    };
  });
}
```

<script lang="ts">
  // Crew ビュー: アクティブタブのペインを 1 体ずつのアイソメなキャラとして上部の帯に描く。
  // 状態は agent-status.ts の PaneStatus に完全に乗る（ここで判定は一切しない）。
  // 動かすのは transform と opacity だけ＝compositor-only（PERFORMANCE.md）。
  import { layout, paneStatus, focusedPane } from "../store/appStore";
  import { leafIds, leafInfoMap, type PaneRole } from "../layout/tree";
  import { STATUS_LABEL, type PaneStatus } from "../core/agent-status";
  import { buildCrew, seatToIso, SEAT_COLS, SEAT_ROWS, TILE_W, TILE_H } from "./model";

  // 床は席の格子より 1 マスずつ外側まで敷いて、キャラが端に立っても床が途切れないようにする。
  const FLOOR = (() => {
    const cells: { col: number; row: number; x: number; y: number }[] = [];
    for (let row = -1; row <= SEAT_ROWS; row++) {
      for (let col = -1; col <= SEAT_COLS; col++) {
        cells.push({ col, row, x: (col - row) * (TILE_W / 2), y: (col + row) * (TILE_H / 2) });
      }
    }
    return cells;
  })();

  // 格子全体の中心。ステージ原点をここへずらして帯の中央に置く。
  const CENTER_X = ((SEAT_COLS - 1) / 2 - (SEAT_ROWS - 1) / 2) * (TILE_W / 2);
  const CENTER_Y = ((SEAT_COLS - 1) / 2 + (SEAT_ROWS - 1) / 2) * (TILE_H / 2);

  let info = $derived.by(() => {
    const m = new Map<number, { role?: PaneRole; label?: string }>();
    if ($layout) leafInfoMap($layout, m);
    return m;
  });
  let crew = $derived(buildCrew(leafIds($layout), info, $paneStatus));

  // ホバー時のツールチップ。状態名は STATUS_LABEL を再利用する（バッジと同じ文言に揃える）。
  function tipText(label: string, status: PaneStatus | null): string {
    return status ? `${label} — ${STATUS_LABEL[status]}` : label;
  }
</script>

- [ ] **Step 1: 入場ロジックを実装**

`<script>` に追加（`tipText` 関数の後ろ）：

```ts
  // 入場: 新しいキャラを最初の 1 フレームだけ帯の左外に置き、次のフレームで席へ移す。
  // 位置の補間は .member の CSS transition（Task 2 で入れた 0.9s）が行うので、
  // JS 側は「もう着席したか」の集合を 1 度だけ更新するだけ＝毎フレームのループは無い。
  //
  // paneId は nextPaneId() の単調増加で再利用されないため、閉じたペインの id が
  // seated に残っても誤って「着席済み」と判定されることはない（掃除は不要）。
  const ENTRY_X = -300;
  let seated = $state(new Set<number>());
  $effect(() => {
    const missing = crew.map((c) => c.paneId).filter((id) => !seated.has(id));
    if (missing.length === 0) return;
    const raf = requestAnimationFrame(() => {
      seated = new Set([...seated, ...missing]);
    });
    return () => cancelAnimationFrame(raf);
  });
```

- [ ] **Step 2: マークアップを入場に対応させる**

`.member` の `style:transform`（Task 2 で書いたもの）を、未着席なら帯の左外を指すように差し替える。
y は席の高さのままにして、水平方向にだけ歩かせる：

```svelte
        style:transform="translate3d({seated.has(m.paneId) ? p.x : ENTRY_X}px, {p.y}px, 0)"
```

> `.member` の `transition: transform 0.9s` は Task 2 で既に入っている。CSS トランジションは
> 要素の初期値からは発火しないので、マウント直後に左外へワープする見た目にはならない
> （最初の描画が左外 → rAF で席へ → そこで初めて 0.9s の補間が走る）。

- [ ] **Step 3: 退場アニメーションを実装**

`<script>` の import に追加：

```ts
  import { fade } from "svelte/transition";
```

`.member` の div に追加：

```svelte
        out:fade={{ duration: 320 }}
```

> 退場は「フェードして消える」に留める。席から歩いて帰る演出は、DOM から消えたペインの
> 座標を別途保持し続ける必要があり（`{#each}` のキーが消えた時点で位置情報が失われる）、
> 得られる効果に対して状態管理が重くなりすぎる。残ったキャラが席を詰めて歩いていく動き
> （Task 2 の `transition: transform`）で「1 人減った」ことは十分に伝わる。
>
> `fade` は opacity しか触らないので、位置決めの inline `transform` と衝突しない。
