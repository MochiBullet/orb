# Crew ビュー再設計 — サイドバーへの移設と差し替え可能なキャラクター

作成日: 2026-08-11
対象: `src/crew/`, `src/chrome/Sidebar.svelte`, `src/App.svelte`, 設定画面, `src-tauri/`（画像の保存のみ）

## なぜ作り直すか

v1.6.0 で配布した Crew ビューを実機で見た結果、次の指摘を受けた。

1. 画面上部の帯が **1/4 も占有していて邪魔**、かつ見た目が良くない
2. キャラクターが単純すぎて **「アクティブかどうか」しか判別できない** — 「これなら要らない」水準
3. マスが 8 席（4×2）もあり、そこまで要らない

つまり現行 Crew は「場所を取る割に、既存のバッジ／INBOX 以上のことを何も教えてくれない」。
本設計はこれを **サイドバー内に収め、状態を文字で明言し、キャラクターを差し替え可能にする** ことで解決する。

## 決まったこと（もっちゃんの選択）

種別は CLAUDE.md の仕分けに従う — **(a)** 欠陥修正、**(b)** 追加、**(c)** 承認済みのものの変更。
(b) と (c) は着手前に個別提示して合意を取ること、が運用ルール。**この表の全行はその個別合意を取り終えている**
（下の「合意の経緯」を参照）。

| 種別 | 論点 | 決定 |
| --- | --- | --- |
| (a) | 配置 | サイドバー内の `CREW` セクション。**幅は 168px のまま広げない** |
| (a) | 席数 | **2 席**。3 体目以降は「他 N 人」と数字で畳む |
| (a) | 並び順 | 手が要る順（既存 `STATUS_PRIORITY` をそのまま流用） |
| (a) | 状態の伝え方 | **吹き出しに日本語テキスト**。色分けはしない |
| (a) | キャラの絵 | アニメ調のちび。**既定は SVG** |
| (b) | 差し替え | 上書きは **1 枚のスプライトシート PNG**（テンプレート同梱） |
| (b) | 名前 | **キャラ枠ごと**に付ける（どのペインが入ってもその枠のキャラが演じる） |
| **(c)** | INBOX との関係 | **Crew が INBOX を兼ねる**（INBOX セクションは廃止） |

### 合意の経緯

この spec の決定は会話の中で 1 件ずつ選択されたもので、リポジトリ側には証跡が残らない。
後から読む人（と監視役）が裏取りできるよう、根拠をここに残す。

- 「上部の帯が占有率的に邪魔・ダサいのでサイドバーの空いているところへ」「マスの数も 2 つくらいでいいかな」
  「キャラクターがシンプルすぎてアクティブかどうかだけの判断しかできなくて、これなら要らないくらいのクオリティ」
  — 再設計そのものの起点。(a) 群はここに直接対応する
- 「色じゃなくて吹き出しで状態を文字で表示にしよう」 — 色分け廃止は解釈ではなく**明示の指示**
- 「キャラクターデータもテンプレ作ってアップロードで差し替えができるようにしたい」
  「設定画面で名前も変えられるようにしよう」 — (b) 2 件も**本人の要望**であって、こちらの付け足しではない
- **(c) の INBOX 廃止のみ、別途「Crew と INBOX が同じ仕事になるが、どうするか」を単独で提示し、
  「両方残す」「INBOX の中にキャラを入れる」を含む選択肢からもっちゃんが「Crew が INBOX を兼ねる」を選んだ。**
  出荷済み機能の削除にあたるため、包括指示に紛れ込ませず個別に確認した

## 設計

### 1. 配置とレイアウト

現行の `.crew { flex: 0 0 25% }` の帯（`App.svelte` 直下）を撤去し、`Sidebar.svelte` 内の
1 セクションとして描画する。表示トグル（`Ctrl+Shift+J` / `crewVisible`）はそのまま活かす。

1 席あたりの構成（サイドバー実寸 168px、padding 込みで実質 144px）:

```
AI ペイン（waiting / attention はここにしか出ない）
┌────────────────────────────┐
│ [キャラ42px] [吹き出し: 要承認 3分12秒] │
│              PLIMAL                    │
└────────────────────────────┘

シェルペイン（running / done / failed のみ）
┌────────────────────────────┐
│ [キャラ42px] [吹き出し: 実行中 0分48秒] │
│              CREFT                     │
│              npm run build             │
└────────────────────────────┘
```

**この 2 種類が混ざらないのは仕様上の帰結**である。`shouldTrackAgentStatus`
（`core/agent-status.ts` / `Terminal.svelte`）が `waiting` / `attention` を AI ペインに限定しており、
シェルペインは OSC133 D 経由の `running` / `done` / `failed` しか取らない。
一方 AI ペインのコマンド行は常に `claude` なので出さない。
したがって **「要承認」とコマンド行が同時に出ることは無い**（モックを描くときに間違えやすい）。

- キャラは **42px**（SVG なので拡大縮小で破綻しない）
- 吹き出しは HTML/CSS（canvas に焼くと日本語が汚れる）。しっぽを左下に出してキャラを指す
- 席全体がボタン。クリックでそのペインへフォーカス＝**INBOX が持っていた挙動を引き継ぐ**

### 2. 席の選び方

**対象はアクティブタブの全ペイン**（シェル・AI を問わない。現行 Crew と同じ `leafIds`）。

`STATUS_PRIORITY = ["attention", "failed", "waiting", "done", "running"]` の順に並べ、上位 2 件を席に着ける。
この配列は既にバッジ・タブ集約・INBOX が共有している単一ソースで、**Crew もそこに乗るだけ**（判定を二重実装しない）。

**状態を持たないペイン（バッジ無し = idle）は最下位**として、上記 5 状態のどれかを持つペインが
2 件に満たないときだけ席に着く。つまり席は常に埋まる（ペインが 1 つしか無ければ 1 席）。

同順位内はペイン ID 昇順で安定させる。席に着けなかったペイン数は「他 N 人」と 1 行で出す。
この行の文言は**席に着けなかったペインの状態によらず一定**にする（「待機中」と決め打つと、
3 体目が失敗している場合に嘘になるため）。

### 3. キャラクターの絵

**既定 = SVG**（`src/crew/char-svg.ts`）。`charSvg(state, baseColor)` が SVG 文字列を返す。

- 状態ごとに変えるのは **腕の到達点 / 目 / 口 / 体の沈み込み** の 4 つだけ
- **腕は必ず頭より後に描く**。試作で腕→胴→頭の順にしたところ、上げた腕が頭の裏に隠れて
  6 状態のシルエットが全部同じになった（＝今回の指摘が再発した）。ちびキャラは頭が大きいので、
  腕を前面に置いて初めてポーズが立つ
- キャラ固有色を 1 つ受け取り、そこから髪・服・影を生成する。**状態色では塗らない**
  （状態で塗ると、差し替えたキャラ固有の色が壊れるため）

ポーズと状態の対応:

| 状態 | ポーズ | 目 | 口 |
| --- | --- | --- | --- |
| running（作業中） | 前傾、両手を前へ＋キーボード | 半目で下向き | 小さく開く |
| waiting（入力待ち） | 片手を挙げる | 通常 | 波線 |
| attention（要承認） | 両手を挙げる、体が浮く | 見開き＋ハイライト | 大きく開く |
| done（完了） | 片手を挙げて親指を立てる | 閉じて笑う | 笑み |
| failed（失敗） | 両腕が垂れ、体が沈む | × | 真一文字 |
| idle（待機） | 直立、両手を下ろす | 通常 | 真一文字 |

**文字とポーズの役割分担**: 状態の *確定* は吹き出しの文字が担い、ポーズは *遠目で気づく* ためにある。
42px では表情の細部は読めないが、「両手を挙げている」は 32px でも分かる。

### 4. 差し替え（スプライトシート）

- 置き場所: **`config_dir()/crew/<slot>.png`**。`config_dir()` は `$XDG_CONFIG_HOME/orb`、未設定なら
  `~/.config/orb`（`src-tauri/src/config.rs`）。`config.toml` / `projects.toml` / `bg-default.mp4` と同じ場所に
  揃える — `%APPDATA%`（Roaming）は orb のどの設定物も使っていないので、新しい規約を作らない
- 形式: **6 ポーズを横一列**に並べた 1 枚の PNG。1 コマは正方形で、`width / 6 = height`
  （コマ幅はファイルから算出するので、64px でも 128px でも受け付ける）
- 並び順は本文書の表と同じ `running, waiting, attention, done, failed, idle` 固定
- 同梱テンプレート: `assets/crew-template.png`（枠線とコマ番号入り）＋ `assets/crew-template.md`（描き方）
- 読み込みに失敗した / コマ数が合わない場合は **既定 SVG に戻したうえで、トーストで理由を出す**
  （#79 のエラー可視化基盤に乗せる。静かに黒画面になった背景動画の再発を防ぐ）
- **検証はフロント側で行う**。`Image` に読ませて `naturalWidth / 6 === naturalHeight` を確かめるだけで済み、
  Rust に PNG デコーダを足す必要がない（`png` クレートは現在エンコード用途でしか使っていない）。
  `src-tauri` 側の責務は **選ばれたファイルを `config_dir()/crew/` へコピーすることだけ**

### 5. 名前と設定

`config.toml` に追加:

```toml
[[crew.slots]]
name = "枠1"
color = "#4fb3a4"
sprite = ""        # 空 = 既定SVG

[[crew.slots]]
name = "枠2"
color = "#9b7fd4"
sprite = ""
```

設定画面（`Ctrl+,`）に `CREW` タブを足し、枠ごとに **名前・色・画像選択（＋既定に戻す）** を置く。
スロットは 2 つ固定（席数と同じ）。

**名前の表示規則**: 枠に名前があればそれを出し、無ければ従来どおりランチャー由来の label、
それも無ければ `pane N`。

### 6. 新しく必要になるデータ

- **経過時間**: `paneStatus` は状態しか持っていないため、状態が変わった時刻を記録する
  `paneStatusSince: Map<paneId, number>` を `appStore` に追加し、`setPaneStatus` が値の変化時のみ更新する
  （同じ値の再設定でリセットしないこと＝経過が伸び続けるのが正しい）。
  **状態が `null` になったとき（`acknowledgePane` / ペイン破棄）は `paneStatusSince` の該当キーも消す**。
  残すと、次に同じペインが状態を持ったときに古い時刻から経過を数えて嘘の数字を出す
- **`idle` の扱い**: `PaneStatus` 型に `idle` は無く、`STATUS_LABEL` にも項目が無い（バッジ無し＝状態未設定）。
  Crew の吹き出しは `STATUS_LABEL[status]` を使い、**状態が無いペインでは「待機」を Crew 側の定数で補う**。
  `STATUS_LABEL` 自体には追加しない（バッジ・通知の意味論を変えないため）
- **直近コマンド**: `osc.ts` が nonce 検証済みのコマンド行を持っているので、ペイン単位で最後の 1 本を
  ストアへ出す。ただし **AI ペインでは常に `claude` としか出ないので表示しない**（シェルペインのみ）

### 7. INBOX の廃止

`Sidebar.svelte` の `INBOX` セクションを削除し、その役割（手が要るペインの一覧＋1 クリックで移動＋
フォーカスで自動確認）を Crew セクションが引き継ぐ。`acknowledgePane` の呼び出し経路は変更しない。

Crew が INBOX より増える点: 手が要るペインが 1 つも無いときに **作業中のペインを見せる**（INBOX は空になる）。

### 8. 削除するもの

- `src/crew/Crew.svelte` のアイソメ床・席格子・入場アニメ（`FLOOR` / `seatToIso` / `ENTRY_X` / `seated`）
- `model.ts` の `SEAT_COLS` / `SEAT_ROWS` / `MAX_SEATS` / `TILE_W` / `TILE_H` / `cellToIso` / `seatToCell`
- `App.svelte` の帯マウントと、それに伴う `.stack` の 25% 確保
- `Sidebar.svelte` の INBOX セクション

## テスト

純関数に隔離して vitest で見る:

- 席の選択（優先度順・同順位はペインID昇順・上限2・あふれ人数）
- 経過時間の整形（0秒〜、分をまたぐ、24時間超は「24時間+」で頭打ち）
- スプライトシートの検証（コマ数・正方形判定・不正なら既定へフォールバック）
- 名前の解決順（枠名 → ランチャー label → `pane N`）

見た目（ポーズが読めるか、42px で成立するか）は **もっちゃんの目視**でのみ確定する。
静的レビューでは腕が頭に隠れている事故を検出できなかった実績があるため、
実装中も 42px と 32px のスクリーンショットを撮って確認する。

## やらないこと

- サイドバーの幅を広げる（168px 固定）
- 席を 3 つ以上に増やす
- 状態を色で表す（文字で言う）
- GIF / APNG などのアニメーション画像の受け入れ
- キャラの歩行・席移動アニメーション（旧実装から引き継がない）
